# Install FrootAI Orchard MCP

This guide shows how to wire the FrootAI Orchard MCP server into the 6 most common MCP clients. Pick the runtime that fits your machine (`npx` for Node, `uvx` for Python — both are byte-equal):

| Runtime | Command |
|---|---|
| npm | `npx -y @frootai/mcp-orchard@latest` |
| Python | `uvx frootai-mcp-orchard[sdk]@latest` |

All snippets below use the **npm runtime**. Replace the `command` + `args` block with the Python form (see [Python alternative](#python-alternative) at the bottom) if you prefer.

## Auth — `frootai login` once, works everywhere

Before configuring any client, sign in once so the MCP server can call paid tools (`orchard.find_play`):

```bash
npm install -g frootai
frootai login
```

This writes a token to `~/.frootai/.token` (mode 0o600). The MCP server reads it automatically — you do NOT pass tokens through client configs. Free tools (`orchard.search`, `orchard.show`, `orchard.install_command`, `orchard.list_pollinations`) work without sign-in.

## Cursor

Cursor reads MCP server configs from `~/.cursor/mcp.json`. Add the `frootai-orchard` entry:

```json
{
  "mcpServers": {
    "frootai-orchard": {
      "command": "npx",
      "args": ["-y", "@frootai/mcp-orchard@latest"]
    }
  }
}
```

Restart Cursor. The MCP server appears in **Settings → Features → MCP Servers** with a green dot when healthy. You can now ask Cursor things like *"find me an Azure RAG accelerator with eval coverage"* and it will call `orchard.search` automatically.

## ChatGPT MCP

ChatGPT supports MCP servers via **Settings → Beta features → MCP servers → Add server**. Paste:

| Field | Value |
|---|---|
| Name | `FrootAI Orchard` |
| Command | `npx` |
| Args (one per line) | `-y`<br>`@frootai/mcp-orchard@latest` |
| Env vars | *(leave blank — server reads `~/.frootai/.token`)* |

Click **Add**. ChatGPT spawns the server and registers the 5 tools.

## Continue (VS Code / JetBrains)

Continue reads `~/.continue/config.json`:

      {
        "transport": {
          "type": "stdio",

Reload Continue (`Continue: Reload Window` from the command palette). The tools appear in the slash-command menu prefixed with `@orchard`.

## Cline

Cline (VS Code extension) reads MCP config from its own settings panel:

1. Open **VS Code → Settings → Extensions → Cline**
2. Scroll to **MCP Servers** and click **Add Server**
3. Fill in:

| Field | Value |
|---|---|
| Server name | `frootai-orchard` |
| Command | `npx -y @frootai/mcp-orchard@latest` |
| Transport | `stdio` |

Save. Cline restarts and the 5 tools appear in the tool picker.

## VS Code (embedded MCP server)

If you have the **FrootAI Orchard VS Code extension** installed, an embedded MCP server boots in-process — no separate terminal or `npx` required. The extension uses a built-in SDK shim (A8.7) that routes through the same `@frootai/mcp-orchard` protocol dispatcher, so tool outputs are **byte-equal** with the standalone npm + Python servers.

### Enabling the embedded server

1. Open **Settings** → search `frootai.orchard.mcpServer`.
2. Set `frootai.orchard.mcpServer.autoStart` to `true` (or run the command palette → *FrootAI Orchard: Start MCP Server*).
3. Optionally pin a port: `frootai.orchard.mcpServer.port` (default `0` = OS picks a free ephemeral port).

The server writes a discovery file at `~/.frootai/vscode-mcp-endpoint.json` (mode `0600`) so other extensions / MCP agents can discover the local endpoint:

```json
{
  "schema_version": 1,
  "url": "http://127.0.0.1:<port>/mcp",
  "transport": "streamable_http",
  "tools": ["orchard.search", "orchard.show", "orchard.install_command", "orchard.find_play", "orchard.list_pollinations"]
}
```

### Auth

The embedded server reads the same `~/.frootai/.token` file the CLI writes. Run `frootai login` in any VS Code terminal to authenticate — the embedded server picks up the token on the next tool call (60-second cache TTL).

### 3-runtime conformance

The embedded server is byte-equal with the standalone npm and Python servers. This is verified by the 3-runtime cross-MCP conformance suite (A9.1) which runs the same contract manifest against all three runtimes and asserts deep equality on every tool-call response.

## Any other MCP client (raw stdio)

Any client speaking MCP spec **2025-03-26** over stdio can use our server. Spawn:

```bash
npx -y @frootai/mcp-orchard@latest
```

The process reads JSON-RPC 2.0 messages from stdin (line-delimited, one JSON per line) and writes responses to stdout. Stderr is reserved for diagnostics.

For Streamable HTTP partners (self-hosted):

```bash
mcp-orchard --http --port 8080
# POST JSON-RPC to http://localhost:8080/mcp
# GET http://localhost:8080/health for the health check
```

## Python alternative

Anywhere you see the npm runtime config, swap in the Python runtime:

```json
{
  "mcpServers": {
    "frootai-orchard": {
      "command": "uvx",
      "args": ["frootai-mcp-orchard[sdk]@latest"]
    }
  }
}
```

(Requires [`uv`](https://docs.astral.sh/uv/) installed — the recommended Python launcher for MCP servers.) The two runtimes produce **byte-equal** results for the same tool call — pick whichever fits your machine.

## Verifying the install

After your client restarts, you should be able to ask it:

> *"Search the FrootAI Orchard for Azure RAG accelerators with eval coverage"*

The agent calls `orchard.search` with `query="rag"` and `where="variety:azure AND trust_badge:eval_proven"` and renders a Markdown table inline. If you see a "tool not found" error, the MCP server failed to start — check the client's MCP log for the stderr output.

## Self-host (on-prem)

Enterprise customers can run the MCP server inside their own VPC / on-prem datacenter using the published Docker image. The container exposes the same `/mcp` Streamable HTTP endpoint as `mcp-orchard --http` plus a `/health` endpoint suitable for orchestrators (Kubernetes / Nomad / ECS):

```bash
docker pull ghcr.io/frootai/mcp-orchard:1.0.0

docker run --rm -p 3000:3000 \
  --read-only --tmpfs /tmp \
  --cap-drop=ALL --security-opt no-new-privileges \
  ghcr.io/frootai/mcp-orchard:1.0.0
```

For per-region pinning, IAM / secrets wiring, cosign verification, and graceful-shutdown semantics, see the [Self-host guide](../enterprise/self-host).
